# Carry AUDJPY のバックテストは、走らせた日によって変わる（2026-09-19）

## 対照が過去ラウンドと合わないとき、疑うべきは案でも計測でもなくスワップだった

並行セッションが FULL 窓（115か月）の対照を初めて取ったところ、
9月9日の `ml/fxrisk1` R001 と**取引数は 2,969 で完全に同じなのに純益がずれた**:

| 窓 | 2026-09-09（R001） | 2026-09-19（F000） | 差 |
|---|---:|---:|---:|
| OOS（55か月） | +119,537 | +117,843 | **−1,694** |
| FULL（115か月） | +379,084 | +375,014 | **−4,070** |

並行セッションは「**ラウンド内で閉じた比較しかしていないので判定には影響しない**」として
原因を追っていなかった。**その判断は正しい**が、原因は追う価値があった。

## 1. 何が動いたか — 全 deal を1行ずつ突き合わせた

`ml/fxqual9/swapdrift.py` で 5,938 行を1対1で比較した。

> **時刻・magic・方向・ロット・価格・SL は、全 deal で完全一致。**
> **違うのは損益だけ。**

枠別に割ると、動いたのは**1枠だけ**だった:

| 枠 | 純益差 |
|---|---:|
| **Carry AUDJPY** | **−4,070** |
| PB USDJPY / PB GBPJPY / RSI USDJPY / RSI EURUSD / RSI GBPUSD / Pair EU/GU / SCA USDJPY / SCA GBPJPY | **すべて ±0 円** |

### ⚠️ この表が出るのは `position_id` で引き直しているからである

生の `magic` で集計すると、**同じ差が2つに割れて「Carry だけ」の判定が落ちる**:

| 集計 | Carry(20260650) | magic 0 | 合計 |
|---|---:|---:|---:|
| **引き直しなし（生の magic）** | −3,388 | **−682** | −4,070 |
| **引き直しあり（position_id → 建玉時 magic）** | **−4,070** | — | −4,070 |

`magic=0` は**テスターが窓末の建玉を強制決済した deal** である（第16報で見つけたもの）。
実体は Carry AUDJPY の建玉なので、引き直せば全部 Carry になる。
`ml/fxqual9/swapdrift.py` はこの引き直しを入れてある（並行セッションの指摘で明示的に検証した）。

### ⚠️ 枠別 CSV（`results.csv` の `*_net` 列）で比べてはいけない

同じ2つを枠別列で比べると、**まったく違う絵**が出る（並行セッションの実測）:

| 枠 | R001 FULL | F000 FULL | 差 |
|---|---:|---:|---:|
| `carry_net` | 56,128 | **105,291** | **+49,163** |
| `pair_net` | 15,093 | 15,048 | −45 |

**この `+49,163` はスワップではない。第16報の配賦修正である。**
`ml/fxrisk1` の `results.csv` は**修正前**の集計で、窓末の建玉が枠から丸ごと落ちている
（R001 FULL の枠の和 325,896 に対しブック 379,084 ＝ **未配賦 53,188**）。
`ml/fxqualcfm` は修正後なので未配賦が 0 である。

そして **53,233 − 4,070 = 49,163** で、下表の窓末建玉（2025-07-15 建玉）の

> 1. **スワップのドリフト**（Carry のみ・保有日数に比例）

## 3. 原因 — テスターは履歴全体に「いまのスワップ値」を当てる

**MT5 のストラテジーテスターは、銘柄仕様の現在のスワップ値をバックテスト全期間に適用する。**
業者がスワップを更新すれば、**同じ設定・同じ期間で走らせ直しても損益が変わる。**

AUDJPY の買いスワップが、9月9日から9月19日のあいだに
**0.01ロットあたり 1日 0.664円ぶん下がった**（1ロットあたり約66円/日）ということである。

### EA 側の可能性は潰した

- EA の取引ログは `DEAL_PROFIT + DEAL_SWAP + DEAL_COMMISSION` を `profit` 列に書いている（EA 3373行）
- この書き出しは **9月9日〜9月18日のあいだに1行も変わっていない**（`git diff 28f5a6e..6f4527d` で確認）
- 同期間に EA には **553行の挿入・50行の削除**が入っているが、
  **Carry 以外の8枠は1円まで完全に一致**している

> [!important] **これは「EA 変更が不変でなかった」ではない。逆である。**
> 9日間・553行の EA 変更が、**8枠すべてで1円も動かさなかった**ことの証明になっている。
> 「既定値で不変」という主張が、2,969取引の上で実測として裏付けられた。

## 4. 何に効くか

| 影響 | 内容 |
|---|---|
| **ラウンド内の比較** | **影響なし。** 同一ラウンドの run は同じ日に走るので、スワップは共通 |
| **ラウンドをまたぐ比較** | **Carry の枠純益は比較できない。** 日が違えば値が違う |
| **FULL 窓ほど大きい** | 保有日数が多いので差も大きい（OOS −1,694 に対し FULL −4,070） |
| **他の8枠** | 保有が短いので実質ゼロ（実測でちょうど0円） |

### 既存の記録への影響

- 第16報の「**Carry の IS 純益の 68%（+52,551円）は窓末の建玉1件**」——
  この **+52,551 は 9月17日時点の値**で、9月9日には **+53,233** だった。
  **窓端に支配されているという結論は変わらない**が、金額は走らせた日の関数である。
- `oanda_fx_risk_sizing_20260915.md` の FULL 純益 +379,084 は、**いま走らせると +375,014 になる。**
  ラウンドをまたいで並べるときは注意が要る。

### Carry を凍結する理由がもう1つ増えた

Carry AUDJPY は既に「各窓7取引・IS 純益の68%が窓末建玉1件」を理由に
**パラメータ掃引を凍結**している（[rejected_strategies.md](rejected_strategies.md)）。
ここに **「バックテストが日をまたいで再現しない」**が加わる。
**改善案を測っても、対照との差にスワップのドリフトが混ざる。**
同じ日に対照と案を走らせているかぎり問題は無いが、
**過去の数字と比べる形の検証はできない。**

## 5. 運用ルールとして

> **対照 run が過去ラウンドと合わないときは、案を疑う前に `ml/fxqual9/swapdrift.py` を回す。**
> 差が Carry だけで、保有日数に比例していれば、それはスワップのドリフトであって
> 案の効果でも計測バグでもない。

```
python ml/fxqual9/swapdrift.py ml/fxrisk1 R001 FULL ml/fxqualcfm F000 FULL
```

**これは `ml/fxqual9` の A000 の判定にも直接効く。**
A000 が W000（+117,843 / 1375取引）とずれた場合、
**まず「差が Carry だけで保有日数に比例しているか」を見る。**
そうであれば第9ラウンドの EA パッチは無実で、ずれはスワップである。
そうでなければパッチを疑う。**この順番を先に決めておく。**
