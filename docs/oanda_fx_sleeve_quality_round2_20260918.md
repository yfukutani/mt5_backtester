## 1. ⚠️ 訂正 — 第15報の「Carry の副作用」は計測バグだった

### 1.1 何が起きていたか

窓の終わりに建ったままだったポジションは、テスターが強制決済する。
**その決済 deal の `magic` は 0 で記録される。**
枠別集計（`ml/fxmargin3/measure.py`）は `magic` を直に引いていたので、その損益は

- ブック全体の `net`（最終残高ベース）には **入っている**
- 枠別の `*_net` からは **丸ごと落ちていた**

という非対称になっていた。第15報はこの差額を
**「FX以外の枠（GOLD・暗号・VBO）の損益」と誤読**した。

**この構成では GOLD・暗号・VBO は1件も発注していない。** 差額の正体は、

| 窓 | 中身 | 額 |
|---|---|---:|
| OOS | Carry AUDJPY の建玉（0.03ロット・@82.401）＋ Pair の片脚（0.01・@1.37983） | **+32,519** |
| IS | Carry AUDJPY の建玉（0.03ロット・@112.981）＋ Pair の片脚 | **+52,506** |

であり、**Carry の退出SMA を入れるとその建玉を早く切ってしまう**、というだけだった。

### 1.2 直した

`position_id` から建玉時の magic を引いて配賦するように変えた
（`ml/fxmargin3/measure.py` と、既存44run を測り直す `ml/fxqual1/reattribute.py`）。
**44run すべてで「枠の和」と「ブック純益」が1円まで一致する**（未配賦0）。

Codex の査読で実データも確認済み:
`entry` は 0/1 のみ・`magic=0` は **107件すべて OUT 側**・
**同一 `position_id` に複数の IN magic は1件も無い**。

> Codex の指摘（将来壊れる筋・未対応）: netting 口座の `DEAL_ENTRY_INOUT` や
> `OUT_BY`（close-by）が出ると、片方の IN magic だけで全損益を決める今の実装では足りない。
> 現在の hedging 口座・現在のダンプ形式では起きないが、形式を変えるときは思い出すこと。

## 2. RSI 3枠の発火機構を、初めて両窓で分離した

`ProcRSI()` の入口は `(rbuy||bbuy||dpb)` の OR（**R**=RSI反転 / **B**=ボリンジャー回帰 /
**D**=ダブルボトム）で、退出は共通の固定SL/TPひとつしかない。
第15報で注文コメントにタグを埋めた（`TagDealTriggers`・既定OFF）。

**回帰試験は両窓で合格**した。`ml/fxqual2` の T000 は `ml/fxqual1` の Q000 と
**純益・DD・取引数・枠別内訳のすべてが完全一致**する（タグ付けは売買を1ビットも変えていない）。

### 2.2 読み

- **USDJPY は「ダブルボトム(D)を含む足」で勝ち、「BB回帰(B)単独」で負ける。両窓で同じ符号。**
  ここだけが、このテーマで初めて出た**両窓で符号が揃った差**である。
- **GBPUSD は B 単独が主戦力**（両窓＋）。RB は OOS＋・IS ほぼゼロ。**落とすものが無い。**
- **EURUSD は勝つ機構が窓で入れ替わる。** B と RB が**両方とも符号反転**している。
  これは「どちらを残すか」の問題ではない。**この枠の入口が窓に対して不安定**という意味である。

> [!warning] **Codex の第1推奨は、この反転を知る前の意見である。**
> OOS の内訳しか渡せていない段階で意見を求めたため、Codex は
> 「EURUSD は RB のみが唯一の強い候補」を第1推奨として返した。
> その後に出た IS では **RB が −3,787・B単独が +10,492 と符号が逆**である。
> **この案は「OOSで選んでISで落ちる」典型のはずで、外れると予想する。**
> それでも `V007` として測る（2run）。予想を先に書いた反証試験は安いからである。

### 2.3 効き幅を先に見積もる

両窓で符号が揃っているものだけを落とす案（USDJPY の R単独・B単独を落とす）の
素朴な足し算は **OOS +2,856円 / IS +1,682円**。月利に直すと

| 窓 | Δ純益 | Δ単利月利 |
|---|---:|---:|
| OOS | +2,856 | **+0.010pt** |
| IS | +1,682 | **+0.006pt** |

**目標（月利6%）に対しては無に等しい。**
それでも測るのは、第14報の21案が**1件も両窓改善しなかった**ので、
「両窓で改善する案が存在するのか」を1件でも作ること自体に意味があるからである。
**収益目標への前進としては期待していない。**

（素朴な足し算が当たる保証も無い。ゲートで落とした足ではフラグを消費しないので、
「単独では建てず合流を待つ」動きになり、落とした取引の分だけ減るのではなく
**別の足で別の取引が生まれる**。だから実測する。
フラグを消費しないという設計は Codex も同じ結論だった。）

## 4. PB GBPJPY の律速 — 推測をやめて数えることにした

第14報で ADX を 30→22.5 まで下げても 115か月で取引が5件しか増えなかった。
**律速は ADX ではない。** では何かを推測で潰すのは、第14報で21案を空振りした形なので止める。

入口は8条件の AND である（買い側）:

| # | 条件 |
|---|---|
| 0 | `up` = 終値 > trendMA かつ fastEMA > slowEMA |
| 1 | `armed` = 押し目待ちフラグ（fastEMA まで押し、slowEMA は割らなかった足の記憶） |
| 2 | 終値 > fastEMA（押し目からの戻り） |
| 3 | 陽線 |
| 4 | 終値 > 2本前の高値 |
| 5 | ADX ≥ 30 |
| 6 | trendMA の傾き ≥ 1.5×ATR |
| 7 | 上位足 D1 close > D1 MA200 |

`PbDiagCounters`（第16報で追加・既定OFF・**カウンタを回すだけで売買に触れない**）で、
各条件について「**その条件以外の7つが全部成立していたバー数**」を数える（leave-one-out）。
`LOO[k] − ALL` が「その条件だけで落ちたバー数」＝絞りの強さになる。
素朴な漏斗（順に絞る）は順序で答えが変わるので使わない。

> Codex の訂正: **D1 MA200 の合流フィルタは既に現行で有効である**（`useHigherTF=true`）。
> 第15報の「次に見るなら MTF合流と armed」のうち、MTF は「新案」ではなく
> **既にある条件が律速かどうか**の問題である。数えれば分かる。

## 7. 目標（月利6%）に対する現在地

| 項目 | 値 |
|---|---|
| 目標 | OOS 幾何月利 **6%** |
| 本番現行（RefCap=78,000・倍率1・複利） | **0.39%/月**・最大DD 5.2% |
| 実行可能な最良（R037・5枠risk%化・倍率2） | **3.02%/月**・最大DD 41.8% |
| 本ラウンドの対照（固定サイジング・単利） | OOS **0.428%** / IS **0.852%** |
| 本ラウンドの前進 | **ゼロ**（両窓改善の実測はまだ1件も無い） |

> [!warning] **枠の質の改善で月利6%に届く見通しは、この第2ラウンドの後もまったく立っていない。**
> 第1ラウンド21案の効き幅は最良でも月利 ±0.1pt の桁で、**そのうえ正の信号は撤回された。**
> 第2ラウンドで唯一「両窓で符号が揃った」USDJPY のダブルボトムですら **+0.006〜0.010pt** である。
> 6% には現行本番（0.39%/月）から **15倍**、必要な差は **+5.6pt/月**。
> **枠ごとの改良でこの桁は埋まらない。**

**Codex も同じ結論である**（原文）:

> 枠の質改善だけで 0.39%/月から6%/月を埋める見込みは、ありません。
> 率直に言えば低いどころか、統計的に期待すべきではありません。（中略）
> 仮に全案が都合よく同方向に当たっても、現実的には +0.1pt/月 前後で、
> 必要な +5.61pt/月 には桁が二つ足りません。

> [!note] **さらに、ここから先は選別バイアスのほうが大きくなる。**
> RSI の機構別は OOS 20〜152件・IS 2〜156件、Pair は 30/56脚、Carry は 7取引である。
> **「良いタグだけ残す」を繰り返すほど、両窓に対する後付けの度合いが強くなる。**
> 第2ラウンドで両窓の符号一致を採用条件に固定したのはそのためだが、
> それでも窓は2つしか無い。

### 埋めるとしたら、どこか（Codex と一致した見立て）

1. **新しい独立したエッジ**。既存機構の横展開は大半が否定済みなので、
   同型のパラメータ探索ではなく、**異なる保有期間・情報源・市場構造**が要る。
2. **目標と制約の再定義**。実行可能最良の 2.18%/月・DD 30.6% から 6% を狙うなら、
   許容DD・レバレッジ・運用資本・「OOS幾何月利6%」のどれかを動かさない限り整合しない。
3. **フォワード実績の蓄積**。特に Carry は実現・未実現・スワップを分け、
   **窓端の無い rolling 評価**に変えること（§1.3）。
