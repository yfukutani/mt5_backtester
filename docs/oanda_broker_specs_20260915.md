# OANDA証券の銘柄仕様を実機で測った — **1注文の上限は 10ロット**（XMは50）（2026-09-15）

**複利の天井を決めているロット上限は、OANDA証券では `10.00`。バックテストに使っている
XM の `50.00` の 1/5 である。**

`docs/oanda_fx_cap_curve_deposit_20260915.md` §3 と
`docs/oanda_fx_deposit_ceiling_20260915.md` が「最優先」としていた確認の答え。

---

## 1. 測り方

発注しない診断EA `experts/SymbolSpecDump.mq5` を両端末にデプロイして短いバックテストを1本回し、
`SymbolInfoDouble` と `OrderCalcMargin` の値を `Common\Files\symbol_specs_<broker>.csv` に出した。

**「そうなっているはず」を測らずに書かない**——同じ日に
「ini の `Leverage=25` が無視されて 1:100 で走っていた」を出しているので、
銘柄仕様も推定ではなく実機の値を取る。

## 2. 実測値（OANDA証券・FX本番口座）

```
server              OANDA-Japan MT5 Live
company             OANDA Corporation
currency            JPY
account_leverage    25          ← 実機の口座レバレッジも25で確認
margin_mode         2           （retail hedging）
```

| 銘柄 | vol_min | **vol_max** | vol_step | contract_size | margin_initial | **1ロットの必要証拠金** | spread |
|---|---:|---:|---:|---:|---:|---:|---:|
| USDJPY | 0.01 | **10.0** | 0.01 | 100,000 | 0（＝レバレッジ計算） | 412,708円 | 23 |
| EURUSD | 0.01 | **10.0** | 0.01 | 100,000 | 0 | 504,496円 | 45 |
| GBPUSD | 0.01 | **10.0** | 0.01 | 100,000 | 0 | 705,255円 | 38 |
| GBPJPY | 0.01 | **10.0** | 0.01 | 100,000 | 0 | 705,255円 | 46 |
| AUDJPY | 0.01 | **10.0** | 0.01 | 100,000 | 0 | 317,684円 | 38 |
| XAUUSD | 0.01 | **20.0** | 0.01 | 100 | 0 | 783,259円 | 2 |

USDJPY 1ロットの必要証拠金 412,708円 は、
`100,000 USD × 103.2 JPY/USD ÷ 25 ≒ 412,800円` と整合する（**レバレッジ25が効いている**）。
`margin_initial=0` なので、証拠金は口座レバレッジから計算される＝シンボル側の上書きは無い。

## 3. XM との差と、結論への影響

| | XM（バックテストで使用） | **OANDA（本番）** |
|---|---:|---:|
| FX 1注文あたり上限 | **50.00** | **10.00** |

XM の 50 は、deal ログで多数の建玉が**ちょうど 50.00** で頭打ちになっていることから確定している。

**今日の測定で「良い」とされた構成は、OANDA では成立しない。**
最良だった X005（重み＋cap80%）の枠別の最大ロットはこうだった——

| 枠 | X005 の最大ロット | OANDA上限 10.0 に対して |
|---|---:|---|
| RSI USDJPY | 50.00 | **5倍超過** |
| RSI EURUSD | 50.00 | **5倍超過** |
| RSI GBPUSD | 50.00 | **5倍超過** |
| PB GBPJPY | 37.88 | **3.8倍超過** |
| PB USDJPY | 33.65 | **3.4倍超過** |
| Carry AUDJPY | 24.57 | **2.5倍超過** |

**6枠すべてが OANDA の上限を大きく超えている。**

> [!danger] **`docs/oanda_fx_cap_curve_deposit_20260915.md` と
> `oanda_fx_windows_lev25_20260915.md` の数字は、OANDA では再現しない。**
> 複利の天井が 1/5 になるので、上限に当たるのがはるかに早い。

### 影響の向きは分かっている（大きさは未測定）

入金感度の実測（第8報 §2）が、**「口座が上限に対して大きいほど月利が下がる」**ことを
示している——50ロット上限のもとで、入金 50万 → 2,000万 で
張り付き率 2.1% → 31.1%、月利 8.80% → 4.81%。

**上限を 50 → 10 にするのは、口座を5倍にするのと同じ向きの操作である。**
50万円 ＋ 上限10 は、おおよそ「250万円 ＋ 上限50」に相当する。
実測の 200万円（8.56%）と 500万円（7.06%）の間なので、**通期OOSで 7〜8.5% 程度**が目安。
ただし**これは外挿であって測定ではない。**

## 4. 次

1. **OANDA端末で本測定を回し直す。** 銘柄名はプレーン名で共通なので
   `mt5_path` を差し替えれば動くはず。ただし——
   - **フィード差**（2026-07の検証: 「tick化しても縮まらず主因はフィード差・一律補正は不適切」）
   - **スプレッド差**（OANDA USDJPY 23 / EURUSD 45 / GBPJPY 46 — XMと比較が要る）
   - **スワップ差**（Carry は「スワップ実行タイミングで数倍ブレる・鵜呑み厳禁」と既に記録済み）
   があるので、**上限だけ直して XM で回しても本番の答えにはならない。**
2. **上限10を前提にした設計。** 上限に当たる枠のロットを他へ回す／1注文を分割する。
   **天井が業者仕様なら、天井の使い方が設計対象になる。**

## 5. 手順上の反省

この測定を回すとき、**共有ロック（`ml/fxmargin3/measure.lock`）を取らずに
`mt5bt` を直接叩いた。** ちょうど `ml/fxeff1/` が同じ端末で走っており、
XM 側の spec run は 2回とも結果を書けずに終わった（OANDA側は別端末なので成功）。

**端末は1台しかない。単発の診断 run でもロックを取ること。**
XM の上限50は deal ログから確定しているので測り直していないが、
手順としては誤りだった。
