# OANDA FX — 枠の質の第11ラウンド（第21報・`ml/fxqualjfl`・14run）

## 主題: **「取引を捨てる」のではなく「ロットだけ抑える」を測る**

第20報で「`risk%` では `lot = リスク額 ÷ SL距離` なので、**分母が小さい取引ほど重い**」
という機構が中心に来た。既存の `ScaFilRangeMin` は**その取引を捨てる**ことでこれを止める。
本ラウンドで追加した `LotFloorMask` / `LotFloorRatio` は
**取引を全部残したまま、ロット計算に渡す SL距離だけを下限で丸める**。
発注時刻も採否も SL価格も TP も変えない。

> [!important] **固定ロット構成では完全に no-op である。**
> `LotRisk()` の `useRisk` 分岐でしか使わないので、固定ロットでは1円も動かない。
> **つまり「固定ロットでの効き幅」ではこの軸の価値を測れない。**
> Codex も独立に同じ形を最優先に挙げた（[codex_round11](codex_oafx_round11_20260919.md)）。

## 1. 方法を1つ直した — 複利では**円建ての枠別損益は「いつ負けたか」を測っている**

複利では枠の円建て純益は `Σ(R_i × 残高_i)` である（`R` は1往復の残高比損益）。
**残高が100倍になる窓では、後半の取引が桁で支配する。**
そこで各往復を **entry時点の残高に対する比率 R** に直してから集計した。
残高経路は deal ログの `profit` 列の累積で再構成でき、**最終残高が1円まで一致する**ことを確認した
（OOS G000: 500,000 → 1,489,367）。

> [!note] **`profit_jpy` 列は使ってはいけない。**
> 累積すると最終残高が 109,684,856 になり、実際の 1,489,367 と合わない。
> JPY建て銘柄で二重に換算されている。`ml/fxmargin3/measure.py` の枠別集計は
> 正しく `profit` を使っており、**間違っていたのは今回の臨時スクリプトの側**である。

## 4. このラウンドの構成（`ml/fxqualjfl`・EA 改修あり・14run）

基準は **F003**（全複利・倍率1 ＋ 採用候補2件）＝ `fxqual10/G000`・`fxqualfloor/H000` と同一。
窓は **OOS / IS**。FULL は採否が決まってから。

| 案 | `LotFloorMask` | `LotFloorRatio` | 内容 | 事前の予想 |
|---|---:|---:|---|---|
| **J000** | 0 | 0 | 対照。G000 / H000 と1円まで一致すること（回帰試験） | 一致 |
| **J001** | 4 | 0.0040 | SCA UJ 分母フロア（OOS 中央値・IS p20 付近） | **プラス** |
| **J002** | 4 | 0.0055 | 同（OOS p85 / IS 中央値） | **プラス**（J001 より大きい） |
| **J003** | 4 | 0.0070 | 同（IS p75 付近） | プラス、ただし頭打ち |
| **J004** | 8 | 0.0055 | **SCA GJ 分母フロア（反証点）** | **マイナス** |
| **J005** | 3 | 0.0055 | PB 2枠 分母フロア | 小さい・符号不明 |
| **J006** | 3 | 0.0070 | 同 | 小さい・符号不明 |

**`ScaFilRangeMin`（捨てる案）との対比がこのラウンドの値打ちである。**
捨てる案は OOS の SCA UJ を 266→49 往復まで削る＝**枠がほぼ消える**。
分母フロアは全部残す。**同じ +150,000 が出るなら、効いていたのは「重み」であって
「取引の質」ではなかった**ことになり、採用形の選択が変わる。

> [!note] **採るのは頂上ではなく台地の内側。** `ml/fxqual6` の slope と同じ作法。
> グリッドの最良点をそのまま採るのは第16報 V007 の失敗の形である。

## 5. EA 改修の中身（既定は完全な no-op）

```
input int    LotFloorMask  = 0;    // bit0=PB_UJ bit1=PB_GJ bit2=SCA_UJ bit3=SCA_GJ
input double LotFloorRatio = 0.0;  // ロット計算に使う SL距離の下限（|dist|/価格）
```

`LotRisk()` の `useRisk` 分岐で、分母だけを `max(実距離, ratio×価格)` に丸める。
`OnInit` で **mask だけ立てて ratio を 0 のまま**にしたら起動を止める——
片方だけ渡すと黙って no-op になり、第16報で踏んだ
「**効かなかった**という結論に化ける」形と同じになるためである。

`chain.ps1` は `fxqualfloor` の完走を待ってからデプロイ・再コンパイルし、
`LotFloorMask` / `LotFloorDist` の存在・ハッシュ一致・`.ex5` の新しさを確認してから走る。
**リポジトリの `.mq5` は 0 errors / 0 warnings でコンパイル確認済み**（別名でコンパイルし、
走行中の `MIX_EA_SIMVERIFY.ex5` には触れていない）。
