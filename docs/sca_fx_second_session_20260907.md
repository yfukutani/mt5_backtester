# SCA USDJPY / GBPJPY の第2セッション横展開 — 棄却（2026-09-07）

**結論:** GOLD で唯一採用できた「第2セッション」を USDJPY と GBPJPY に横展開しても
**まったく機能しない。71案・142run で両窓とも黒字の案はゼロ。**
12ファミリーすべてが両窓とも中央値マイナス。**棄却。**

特に GBPJPY は IS 中央値 **−65,589円**（最悪 −141,188円）と大きく負ける。
**第2セッションはGOLD固有の現象**であり、SCA機構の一般的な性質ではない。

---

## 1. なぜ測ったか

GOLD の第2セッション（13-15時）は 2,500案超を測って唯一採用できた施策である
（`lot_multiplier_recheck_20260906.md` で円建て再判定を経て確定）。

SCA USDJPY(20261000) と SCA GBPJPY(20261001) はどちらも**レンジ 0-9時・締切12時・
強制決済22時**で、**12-22時が丸ごと未使用**。GOLD の第2セッション導入前と
まったく同じ構造なので、同じ横展開が効くかを測った。

## 2. 実装と測定

`MIX_EA_SIMVERIFY.mq5` に別magicの枠を2つ追加（既定OFF）:
**20261006（USDJPY 第2）** と **20261007（GBPJPY 第2）**。
親枠には一切触れていない。既定値は親枠の設定を引き継ぎ、レンジ窓だけ
GOLD の当たり所（13-15時）に置いた。

USDJPY 36案 / GBPJPY 35案を**別々に**掃いた（同時に有効にすると寄与が分離できない）。
71案・IS/OOS の **142run 全成功**。親枠は全runで完全に不変
（IS `sca_uj 18,563 / sca_gj 73,773`、OOS `−2,224 / 42,219`）。

### この2枠は OANDA本番ブックの構成要素

XM本番ブック（GOLD 2枠＋暗号3枠）には入っていない。OANDA 5端末は LiveUpdate で
使用不能なので、**XM端末・XM銘柄で測った**。本番判断の前にOANDAでの再測定が要る
（GOLD の各ラウンドと同じ扱い）。ただし本ラウンドは全案不合格なので再測定は不要。

### ⚠️ 掃引を最小構成に落とした理由と、その代償

OANDA本番相当の11枠を有効にすると多銘柄の読み込みで **1run 455秒**かかり、
142runで18時間になる。枠が加算的であることは各ラウンドで確認済みなので、
掃引は**親枠＋新枠だけの最小構成**に落とした（129秒/run・3.5倍高速）。

ただし加算性は完全ではない。中心点X001をフルブックと最小構成で比べると:

| | フルブック | 最小構成 |
|---|---:|---:|
| 新枠の取引数 | 229 | **229（一致）** |
| 新枠の純益 | −1,264 | **−4,830（3,566円の差）** |
| 親枠 | 18,563 / 328取引 | **18,563 / 328（完全一致）** |

**取引集合は同一なのに損益が3,566円ずれる。** これは既知の「枠を1つ足すと
既存枠の損益が約3,530円動く」現象（テスターの約定処理の差）と同じ大きさ。

GOLD のラウンドでは新枠の寄与が 7.5万〜12万円だったので無視できたが、
**本ラウンドは寄与がほぼゼロなのでこの誤差が効く。** そこで
**寄与が ±10,000円未満の案はノイズと区別できない**という下限を置いた。
±10,000円を超えた58案のうち両窓正はゼロなので、結論はこの下限に依存しない。

## 4. なぜ効かなかったか

GOLD の 13-15時 は**ロンドン午後からNY序盤への移行帯**で、そこに形成されるレンジを
抜ける動きに情報があった（`sca_gold_second_session_grid_20260906.md`）。

USDJPY と GBPJPY の SCA が効いているのは **アジア時間（0-9時）に作られた狭いレンジが
ロンドンオープンで抜ける**という、その通貨ペア固有の構造である。
欧州・NY時間に改めてレンジを取っても、**すでに方向が出ている中でのブレイク判定**に
なり、往復で削られる。GBPJPY はロンドン時間のボラティリティが特に高く、
損失が桁違いに大きいのはそのためと読める。

**第2セッションはGOLD固有の現象であって、SCA機構の一般的な性質ではない。**
これは GOLD の結論を弱めるものではないが、**横展開の期待値をゼロに見積もるべき**
ことを意味する。

## 5. 判断

**棄却。** 本番EAへの実装は行わない。検証EAのラボは既定OFF
（`Sca5Enable=false` / `Sca6Enable=false`）のまま残すので本番の挙動には影響しない。
