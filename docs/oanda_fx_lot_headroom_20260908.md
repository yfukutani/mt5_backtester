# OANDA FX の倍率余力と枠別重み — 月利 +1.22ポイント（2026-09-08）

**結論:** OANDA FX 9枠は現行 `GlobalLotMult=1` で、入金50万に対する円建てドローダウンを
**9.7% しか使っていなかった**（XM側は x4 で 25.8%）。

**`Mult_SCA_GBPJPY=0.5` / `Mult_CARRY=0.5` / `GlobalLotMult=5`** にすると、
DD予算30%の範囲内で **OOS窓の月利が 0.43% → 1.65%（+1.22ポイント）**。

これは新しい収益源ではなく**資金の使い方の是正**である。

---

## 1. なぜここを見たか

Codexによる未着手項目の調査（2026-09-07）で、FX側のパラメータ改善は
`param_reopt` / `codex500` / `codex1000` / `codex2000` / `tradeoff8` / `oafx_dd` /
`oafx_dd2`（利益保護だけで1000案）で広く掘り尽くされており、
**残った未着手案を全部足しても入金50万に対して月利 +0.016ポイント程度**しか
見込めないと判明した。目標の +1ポイント/月 には桁が2つ足りない。

一方 XM側では、倍率の再検討（`lot_multiplier_recheck_20260906.md`）が
月利を1ポイント単位で動かせた唯一の軸だった。**同じ分析がFX側では一度も
行われていなかった。** `GlobalLotMult` は既定1のままである。

## 2. ⚠️ 測定設定の誤りを1件訂正

最初の測定で `RefCap_*` を指定せず、**検証EAの既定 0（＝口座equity基準で複利）**で
回してしまった。本番の `MIX_EA_OANDA.mq5` は **78000（＝固定配分で非複利）**である。

その結果 x1 のISが 9.3%/月、x4 が x1 の16倍、x8 は24取引で口座破綻という
明らかな異常値になった。**x4/x8 の線形性検証を入れていたため即座に検出できた。**
無効な結果は `ml/fxmult1/results_refcap0_INVALID.csv` に残してある。

以後 `BASE` に `RefCap_PB_USDJPY / RefCap_PB_GBPJPY / RefCap_CARRY = 78000` を明示。

## 3. ⚠️ ロット丸めで x1→x2 が超線形。内挿できない

XM側は全枠固定ロットで円建て損益が倍率に厳密比例した（実測ずれ 0.0%）ので、
x1 の deal ログを n 倍すれば足りた。**FX側では成立しない。**

PB USDJPY / PB GBPJPY / Carry が risk sizing で、RefCap に対するリスク額から
ロットを出し、そこにロットステップの丸めが入る。x1 では丸めで落ちる割合が大きい。

| 窓 | x1→x2 | x2→x3 | x3→x4 |
|---|---:|---:|---:|
| FULL 純益の増分 | ×2.17 | +444,170 | +445,637 |

**x1→x2 だけが超線形（2.17倍）で、x2以降はほぼ線形。**
つまり **現行の x1 は丸めによる取りこぼしが最大の、最も効率の悪い設定**である。
倍率を上げると取引量の効果に加えて丸め損失の減少分が約8%上乗せされる。

したがって倍率ごとに実測が必要で、測っていない点を内挿してはいけない。

XM側は全枠に分散していたが、**FX側は1枠が支配的**。しかもその枠は最大の収益源でもある。
これが「枠の中身を直す」のではなく「**重みを変える**」という発想につながった。

（SCA GBPJPY のDD削減そのものは `oafx_dd` / `oafx_dd2` で1000案超を測って採用ゼロ。
重み変更は別の軸で未着手だった。）

## 6. 枠別重み × 全体倍率（45案90run 全成功）

### 判定方法

**両窓ともDD予算内に収まる設定の中で、OOS窓の月利が最大のもの。**

IS と OOS ではDD水準が大きく違うため、窓ごとに独立して「予算内の最大」を選ぶと、
IS で予算超過している設定が OOS 側の1位に出てしまう。運用で予算を守るには
**両窓とも予算内**である必要がある（拘束DD＝両窓の大きいほう）。
期待値は **OOS の月利**で見る（IS はパラメータ選択に使った期間なので楽観的）。

### 結果

| DD予算 | 推奨 | 設定 | OOS月利 | **現行差** | IS月利 | 拘束DD |
|---|---|---|---:|---:|---:|---:|
| 20% | W042 | 重み0.5/0.5・倍率3 | 0.98% | +0.54pt | 2.03% | 16.7% |
| 25% | W043 | 重み0.5/0.5・倍率4 | 1.29% | +0.86pt | 2.77% | 22.4% |
| **30%** | **W044** | **重み0.5/0.5・倍率5** | **1.65%** | **+1.22pt** | 3.49% | 28.5% |
| 35% | W045 | 重み0.5/0.5・倍率6 | 1.96% | +1.52pt | 4.24% | 34.1% |

すべて `Mult_SCA_GBPJPY=0.5` かつ `Mult_CARRY=0.5`。

### 重みを変える意味はあった

同じ拘束DD水準で「全重み1のまま倍率だけ上げる」場合との比較:

| 重み変更あり | 全重み1 |
|---|---|
| W045: DD 34.1% → OOS **1.96%** | W004: DD 37.6% → OOS 1.87% |
| W042: DD 16.7% → OOS **0.98%** | W002: DD 18.9% → OOS 0.92% |

**より小さいDDで、より高い月利。**

`Mult_SCA_GBPJPY` は 0.25 では収益源を削りすぎ、0.75 では削減が足りず、**0.5 が最適**。
重みを上げる方向（1.5・2.0）は全て劣後した。

## 7. 推奨設定

```
GlobalLotMult      = 5      // DD予算30%の場合。20%なら3、25%なら4、35%なら6
Mult_SCA_GBPJPY    = 0.5
Mult_CARRY         = 0.5
（他の Mult_* は 1.0 のまま）
RefCap_PB_USDJPY   = 78000  // 本番の既定どおり
RefCap_PB_GBPJPY   = 78000
RefCap_CARRY       = 78000
```

**EA改修は不要。** すべて既存の input である。

## 8. 本番投入の前に必要なこと

1. **OANDA端末での再測定（必須）。** 本測定はXM端末・XM銘柄。本番はOANDAで
   フィードとスプレッドが違う。OANDA 5端末は MT5 の LiveUpdate に捕まって
   使用不能なので、その解消後。
2. **実口座残高の確認。** 本測定は入金50万円を前提にしている。実際の残高が違えば
   推奨倍率も変わる。`RefCap=78000` は risk% 枠の配分額であり口座残高ではない。
3. 倍率を上げるとロット・証拠金・スワップの絶対額が増える。**証拠金維持率**が
   実口座で足りるかの確認。本測定はレバレッジ25で回している。
4. フォワードでのDD実測。本測定の拘束DDはIS期間の1エピソード（536日）に依存しており、
   **将来の最悪期がこれと同じ形とは限らない。**
