## Q3. cap と維持率

### cap70 の通期 OOS

**S070 OOS は走らせる価値があります。捨てるべきではありません。** 見込み: **高**。

理由は、失敗がロスカットではなく **14.6秒での起動失敗**だからです。W1〜W3 はすべて完走しており、月利は 8.95%、6.57%、4.45%、中央値 6.57%でした。通期 OOS の空白を「W3 の残高DD 57.8%」だけで埋めるのは、証拠の種類が違います。

ただし、採用基準は厳しくすべきです。

- 通期 OOS の事前予想: **6.2%/月**
- 完走しても、W3 残高DD 57.8%に加え、**equity DD と最小維持率を必ず回収**
- equity DD が 70〜80%級、または最小維持率が 120%近傍なら、月利が 6%を超えても実運用候補にはしない
- 100%ロスカットの口座で「建て直後143%」は、損失許容幅が約30%ではなく、スプレッド・マージン変動も含むので実際にはさらに狭い

### 現 input で守れるか

**守れません。** `MarginCapPct` は発注時に `使用証拠金 / equity` を制限するだけです。`Bud_*` も発注予算であり、建玉後に価格変動で維持率が落ちることへの自動反応ではありません。`MasterEnable` は手動停止で、バックテスト上の自動保護ではありません。

最小改修は二段階に分けるのがよいです。

1. **新規停止だけの最小版**

   - `MinMarginLevelPct=0`：0 は無効
   - `ResumeMarginLevelPct=0`：ヒステリシス。例 180% / 220%
   - `MarginGuardMask`：対象枠を絞るなら bit mask、0なら全枠

   `ACCOUNT_MARGIN_LEVEL < MinMarginLevelPct` の間、全新規注文を止め、`ResumeMarginLevelPct` を超えたら再開します。これは損切りではなく、悪化中の証拠金追加使用を止めるだけです。

2. **100%を実際に守る版**

   - `MarginEmergencyPct=0`：例 135%
   - `MarginReduceFraction=0`：例 0.5
   - `MarginReducePolicy`：含み損が大きい順、または必要証拠金が大きい順

   維持率が緊急閾値を割れば、一回だけ建玉を部分決済して維持率を回復します。これは戦略出口を壊すので、まずは A09 として独立に OOS/IS を測るべきです。

私なら cap50 を当面の比較基準にし、ガードの初期値は **新規停止 180% / 再開 220% / 緊急削減 135%** から始めます。cap70 の建て直後143%では、新規停止だけでは遅すぎます。
