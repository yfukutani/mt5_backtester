## 2. 動機 — Carry が判定の土台を壊していないか

`T000`（倍率1・完全複利・候補3件）の枠別純益は次のとおり。

| 枠 | OOS 純益 / 取引数 | OOS 構成比 | IS 純益 / 取引数 | IS 構成比 |
|---|---:|---:|---:|---:|
| **Carry AUDJPY** | **341,439 / 7** | **23.9%** | **2,754,029 / 7** | **56.8%** |
| SCA GBPJPY | 426,099 / 621 | 29.8% | **−719,706** / 683 | −14.9% |
| PB GBPJPY | 387,525 / 15 | 27.1% | 1,027,109 / 13 | 21.2% |
| PB USDJPY | 107,369 / 13 | 7.5% | 731,148 / 49 | 15.1% |
| RSI GBPUSD | 103,360 / 62 | 7.2% | 206,436 / 65 | 4.3% |
| RSI USDJPY | 54,494 / 68 | 3.8% | 298,458 / 90 | 6.2% |
| SCA USDJPY | 6,026 / 103 | 0.4% | 215,491 / 214 | 4.4% |
| RSI EURUSD | 3,163 / 269 | 0.2% | 319,501 / 275 | 6.6% |
| Pair EU/GU | 1,984 / 30 | 0.1% | 13,057 / 56 | 0.3% |
| **合計** | **1,431,459** | 100% | **4,845,523** | 100% |

> [!warning] **IS 純益の 56.8% を、Carry が 7取引で出している。**
> そして Carry の損益は MT5 テスターの「**現在のスワップ率を全履歴に一律適用**」
> という近似に支配される。同一設定・同一取引数でも、走らせた日が違うだけで
> Carry だけが動くことを実測済みである（FULL −4,070円・
> [swap drift](oanda_fx_carry_swap_drift_20260919.md)）。
> さらに古い記録では、**スワップ率の瞬間値が変わっただけで Carry 単枠が
> +353,277 → +1,685,950（取引数は42で完全一致）**になっている。

**ユーザーの既定方針は「IS 優先」である。** その IS の過半が、7取引と
非履歴的なスワップ近似に乗っているなら、**我々は13ラウンドかけて
「Carry のスワップ仮定の上での局所最適」を磨いていたことになる。**

Codex にこの懸念の当否を問うたところ:

> **「懸念は正しいです。ただし『全探索がCarryスワップを直接最適化している』という
> 表現は少し強すぎます。」**
> 「複利では、他枠の変更がequity経路を変え、Carryのロットと損益にも波及するため、
> **『Carryは全案で共通だから相殺される』とも言い切れません。**」
> 「ただし、**Carryを除いた8枠だけを新しい主判定ブックにするのも不適切**です。
> Carryを外せば資金経路が変わる別構成であり、9枠ブックからCarry損益を
> 引き算しても答えにはなりません。」

### ⚠️ 引き算では答えられない（第22報で確定済み）

**複利では枠別損益はブックの分解ではない。** 枠を外すと、その枠の損益以上に
ブックが減ることがある（他の8枠に回る資金が減るため）。
逆に、稼いでいない枠を外すとブックが増えることもある（証拠金が空くため）。
**だから9本すべて実際に走らせる。**

## 3. 28run の設計

すべて **候補3件・完全複利（`FxRiskMask=31` / `FxRiskPct=0.5`）・`MarginCapPct=90`**。
cap90 は [実行可能性](oanda_fx_executability_20260919.md) が「実用域」と確認した水準。

| 案 | 倍率 | 内容 |
|---|---:|---|
| **V000** | 1 | **回帰試験。`E002` と一致すること**（OOS 1,431,459 / IS 4,966,997） |
| **V001** | 1 | **Carry AUDJPY を外す** ← 最優先 |
| **V010** | 2 | **回帰試験。`E005` と一致すること**（OOS 3,491,431 / IS 30,121,151） |
| **V011** | 2 | 倍率2・**Carry 抜き** |
| **V012** | 3 | **倍率3・cap90（未測定）**。破綻するかを先に見る |
| **V013** | 3 | 倍率3・**Carry 抜き** ← **倍率の律速が Carry かの答え** |
| V002 | 1 | SCA GBPJPY を外す |
| V003 | 1 | PB GBPJPY を外す |
| V004 | 1 | PB USDJPY を外す |
| V005 | 1 | RSI GBPUSD を外す |
| V006 | 1 | RSI USDJPY を外す |
| V007 | 1 | RSI EURUSD を外す（OOS 3,163円/269取引＝実質ゼロ・証拠金だけ食う） |
| V008 | 1 | SCA USDJPY を外す |
| V009 | 1 | Pair EU/GU を外す（OOS 1,984円/30取引＝最小） |

> [!important] **枠を外すのは `En_*=false` であって `Mult_*=0` ではない。**
> `Clamp()` は cap で 0 になったロットを `MathMax(mn, ...)` で**最小ロットに戻す**
> （[EA 1862行付近](../experts/MIX_EA_SIMVERIFY.mq5)）ので、
> **`Mult_CARRY=0` では枠は止まらず 0.01ロットで建ち続ける。**
> 第16報系の「`Mult_*` が cap の下で効いていなかった」発見と同じ穴である。

**回帰試験の許容幅を置いた。** Carry のスワップ・ドリフトがあるので
「1円も違わないこと」を停止条件にすると、無害なドリフトでラウンドごと落ちる。
**乖離 0.5% を超えたときだけ止める。** それ未満は `DRIFT rel=…` として記録し進む。

**測定順は V000 → V001 → V010 → V011 → V012 → V013 → LOSO 8枠。**
途中で止まっても、判断に効く側から埋まる。
