# OANDA FX — 枠の質の第5ラウンド（第17報・`ml/fxqual5`）

## ⚠️ 撤回 — 「SCA GBPJPY の09時除外」は両窓とも符号が逆だった

`docs/oanda_fx_last_axes_20260915.md` §1 は、取引ログを発注時刻で切り直して
**「09時のブレイクは IS でも OOS でも赤字である。IS だけを見て09時を切ると、
OOS で +31.0%。これは期間をまたいで再現した、数少ない本物の入口フィルタである」**
と結論していた。

**MT5 で走らせたら、両窓ともマイナスだった。**

| 窓 | SCA GBPJPY 枠純益 | deal数 | **切り直しの予測** | **実測** |
|---|---:|---:|---:|---:|
| OOS | 42,219 → **35,402** | 621 → **591**（−30） | **+13,093** | **−6,817** |
| IS | 73,773 → **70,125** | 684 → **647**（−37） | **+7,646** | **−3,648** |

ブック全体では **OOS 117,843 → 111,026 / IS 255,445 → 251,797**。
**単利月利は OOS 0.428% → 0.404%・IS 0.852% → 0.839%。**
DD は OOS が悪化（残高 5.27%→6.04%）、IS はわずかに改善（7.35%→7.06%）。

### なぜ外れたか — 機構は測る前に特定できていた

`ProcSCA()`（`experts/MIX_EA_SIMVERIFY.mq5`）:

```
if(dist>0 && ScaFilEntryOK(i,true,ask,dist,dt.hour)){
   ...
   if(lotL>0.0 && trade.Buy(...)) S[i].scaTradedL=true;   // ← 成功したときだけ立つ
}
```

**「1日1発」のフラグ `scaTradedL` / `scaTradedS` は、発注が成功したときにしか立たない。**
`ScaFilEntryOK` が09時の発注を止めても、その日の枠は終わらない。
ブレイク条件（`close1 > scaRangeHigh + buffer`・GBPJPY は `buffer=0`）は
**価格がレンジの上に留まっているかぎり10時・11時の足でも成立し続ける**
（発注可能時間は 9・10・11時）。

- SL は `scaRangeLow` 固定なので、**遅く入るほど不利**になる。
- 利益の大半は22時の強制決済から出ている（TP到達は 3〜7%）ので、
  **「より高く買って、同じ時刻に決済する」**だけになる。

**切り直しは269件・294件が消えると言っていたが、実際に消えたのは30件・37件である。**
残りは消えずに**後ろへずれた**。

> [!important] **取引ログの切り直しは行を消すだけだが、EA は消さずに後ろへずらす。**
>
> これは `ml/fxqual5` を走らせる前に
> [oanda_fx_sleeve_quality_round3_20260919.md](oanda_fx_sleeve_quality_round3_20260919.md) §3.5.1 に
> **「X001 の改善は切り直しより小さく出るはずで、場合によっては符号が逆になる」**
> と書いてある。**予想どおりに外れた。**

### この失敗の本体は「未測定のまま結論が doc に載る経路」である

2026-09-15 の記述は、**確認runを取る前提**で書かれていた:

> fxrisk3 の測定が終わり次第、`ScaFilMask=2` / `ScaFilHourFrom=10` / `ScaFilHourTo=11` で
> MT5 の確認runを1本取る（EAバイナリの差し替えが要るため、現在の掃引中は実施できない）。

**その1本は4日間・3ラウンド・92run のあいだ、一度も取られなかった。**
そして全ラウンドの `results.csv` で `ScaFilHourFrom` は **44run すべて −1（無効）**だった。

気づいたのは、**Codex が同じ案を第4ラウンドの第1推奨として独立に出してきたから**である。
`rejected_strategies.md` に「棄却」でも「採用」でもない**「未判定」の欄が無かった**ことが
直接の原因なので、そこに1節を足した。

> [!note] **教訓（2つ）**
> 1. **「あとで確認runを取る」と書いた案は、書いた時点では未検証である。**
>    索引に「未判定」として載せない限り、それは**結論として引用され続ける。**
> 2. **ログの切り直しで閉じられる案と、閉じられない案がある。**
>    「その注文が出なかったら何が起きたか」は、**EA の状態機械を読まないと分からない。**
>    今回は読めば分かった（そして読んで当てた）。**読まずに切り直しただけの結論は使えない。**

### 判定条件 — 「そのゲートは日内で解除されるか」

並行セッション（第18報）が、この失敗の一般形を出してくれた。**こう切ればよい:**

| ゲート | 日内で解除されるか | 切り直しは使えるか |
|---|---|---|
| **時間帯**（`ScaFilHourFrom/To`） | **される**（10:00 に解除） | **使えない** |
| レンジ幅（`ScaFilRangeMin`） | されない（9時に幅が確定） | 使える見込み |
| 方向（`ScaFilBuyOnly`） | されない | 使える見込み |
| リバーサル条件（`ScaRevOnlyMask`・第18報） | されない（`scaDrift` は9時に確定） | 使える見込み |

**ゲートが日内で解除されるなら、止めた発注は「消える」のではなく「解除後の足へずれる」。**
時間帯ゲートだけが解除されるので、**そこだけが外れた。**

裏付けとして、並行セッションが `ml/fxqual4` W000 の約定ログで
**「日×方向あたりの建玉は高々1件」が 1,899件すべてで成立（例外ゼロ）**を確認している。
解除されないゲートで落とした「日×方向」は、**消える建玉がちょうど1件で、代わりに出るものが無い。**

また、両者が独立に数えた09時の件数（GJ OOS 269 / GJ IS 294 / UJ OOS 51）が一致したので、
**切り直しの母数の取り方そのものは正しかった。** 間違っていたのは
**「その行を消せば、その損益が消える」という因果の仮定**のほうである。

> [!important] **いちばん短い言い方（並行セッションの定式化）:**
> **切り直しが出す数字は「その群の損益」であって、「その群を消したときの差分」ではない。**
> **両者が一致するのは、消した行が他の行に影響しないときだけである。**
>
> 今回は「消した行が、同じ日の後ろの足に新しい行を生む」という形で影響していた。
> `ScaFilRangeMin` や `ScaRevOnlyMask` のように日内で解除されないゲートなら影響しない——
> **ただし cap を入れると `Clamp()` が枠をまたいで効くので（第13報）、
> その日に他の枠が建てられる量が変わる。cap を入れた瞬間に全部影響する側へ倒れる。**

> [!note] **buffer が効かなかった理由**（並行セッションの読み・こちらも同意）
> `close1 > scaRangeHigh + buffer` は**レンジ高値という固定値に対する条件**なので、
> 一度成立したら価格がレンジ内へ戻らないかぎり次の足でも成立し続ける。
> **buffer は「最初にいつ成立するか」をずらすだけで、「成立し続けるか」には効かない。**
> USDJPY の再入場率が高かったのは、buffer 0.10 のぶん**そもそも成立が遅く、
> 成立したときには既に十分抜けている**ためと読める。

### 建値ストップの母集団について（並行セッションへの訂正）

並行セッションは「+1.0R 以上で**終わる**取引は OOS 16.1% しかないので、
建値ストップが触れる母集団は小さい」と見積もった。**ここは違う。**

建値ストップは「+1.0R で終わった取引」ではなく **「+1.0R に一度でも触れた取引」**に発火する。
母集団は `(終値が ≥1.0R)` ＋ **`(1.0R まで伸びたが、そこより下で終わった)`** で、
**後者こそがこの案の狙っている当の集合**である。

**そして後者は約定ログから数えられない**（deal ログには建値・決済値・SL・TP しか無く、
保有中の最大含み益が残っていない）。つまり:

- **「救える上限が小さい」とは言えない。上限は約定ログでは測れない。**
- 一方、**削るリスクの側（1.0〜1.9R 帯・OOS 9.0%・R計 +75.8）はログから測れる。**
- **「害は事前に測れて、益は事前に測れない」**という非対称になっている。
  **ログで閉じられない唯一の軸だから、測る価値がある。**

> [!warning] **それでも期待はしていない。**
> SL満額（≤−0.95R）が OOS 32.9% ある以上、**1.0R に触れる前に死ぬ取引が多数派**である。
> `ScaBETriggerR=0.5`（Z002）は母集団を増やすが、**0.5R は SL 距離の 1/4 しか
> 動いていない地点**なので、ノイズで建値に戻される取引が急増するはずである。
> **Z002 が最も悪くなると予想する。**
