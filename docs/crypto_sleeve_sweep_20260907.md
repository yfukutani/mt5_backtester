# 暗号枠のパラメータ掃引 — 棄却、および「DDの床」の発見（2026-09-07）

**結論1:** BTC funding逆張り枠と BfxRev枠のパラメータ掃引は**棄却**。
両窓で改善したのは 41案中4案、最良でも **+0.014%/月(IS) / +0.0075%/月(OOS)** と
無視できる規模。しかも感度は非単調で台地を作らない。

**結論2（副産物・こちらが重要）:** ブック全体の最悪ドローダウンには**床**がある。
**2026-03-02 のたった1日・2取引（SCA GOLD第1 −16,751円 と PB GOLD −15,215円）で
−31,966円**。暗号枠を何をしてもこの床は下がらない。
**倍率の上限を決めているのは、この1日である。**

---

## 1. なぜ測ったか

GOLDの時間帯は9-11時・13-15時で尽き（`sca_gold_fourth_session_20260906.md`）、
倍率も限界が見えた（`lot_multiplier_recheck_20260906.md`）。
暗号3枠はFULL窓で135,931円（純益の18.6%）を稼いでおり、伸ばす余地を探した。

BTC funding枠とBfxRev枠には既に入力（`FundThreshold` / `FundMaxHold` /
`BfxDropPct` / `BfxLookbackDays` / `BfxHoldDays`）があり、**EA変更なしで掃引できる**。

## 2. 測定

41案・IS/OOS の82run、**全成功**。基準は XM本番構成＋採用済みの第2セッション（S2046）で、
両暗号枠は EA既定値（C001）。GOLD枠は全82runで完全に不変
（IS `196,940 / 179,120 / 123,237`、OOS `20,752 / 52,540 / 20,733`）。

FULL窓は全案では回していない。暗号枠を有効にすると BTCUSD/ETHUSD の日足読み込みで
**1run 321秒**（GOLD単体の99秒の3倍以上）かかり、41案×3窓では約14時間になるため。

## 3. ⚠️ 円建てDDによる判定が成立しなかった

前ラウンドで確立した判定式は「**純益倍率 > 円建てDD倍率**」だった。これを当てると
「3窓合格6案」と出たが、**中身を見ると判定基準の穴だった。**

IS窓の円建てDDは、41案すべてで**2つの値しか取らない**。

| DD | 案数 | 落ち込みの正体 |
|---:|---:|---|
| 34,587円 | 22案 | 2024-05-23〜09-11 の110日間（全枠に分散） |
| **31,966円** | 19案 | **2026-03-02 の1日**（SCA第1 −16,751 と PB GOLD −15,215 の2取引） |

2024年の山には BTC funding の1取引 −7,949円 が含まれている。fundingのパラメータを
変えてその1取引が消えると、山が 31,966 を下回り、**最悪DDが別の日に切り替わる**。

つまり観測された「DD 7.6%改善」は、暗号枠が良くなったのではなく
**1取引の有無による離散的なジャンプ**である。しかも切り替わった先はGOLDの1日イベントで、
**暗号枠のパラメータでは絶対に下げられない床**である。

最大DDは1本の資産曲線から取る極値統計なので、こういうことが起きる。
`sca_gold_third_session_20260906.md` の訂正と同じ性質の罠で、
**枠の取捨や小さな施策の判定に最大DDを使うと、単一イベントに支配される。**

（同じ理由で、直前に試した「DD寄与の大きい枠を抜く」という検討も失敗している。
FULL窓では「ETHを抜く」が純益÷DD比 +4.5% と出るのに、OOS窓では「BfxRevを抜く」が
+59.2% で、抜くべき枠が窓ごとに入れ替わる。`ml/mult1/dd_attribution.py`。）

## 5. 判断

**棄却。** 暗号枠のパラメータは既定値のままとする。

## 6. 次に効くのはここ — 2026-03-02 の1日

本ラウンドの副産物として、**倍率の上限を決めている実体**が特定できた。

```
2026-03-02  SCA GOLD第1  −16,751円（1取引）
            PB GOLD      −15,215円（1取引）
            合計         −31,966円 ＝ 入金50万の 6.4%
```

**GOLD の2枠が同じ日に最大級の損失を出している。** 入金50万・DD予算30%なら
踏める倍率は 150,000 ÷ 31,966 = **x4.69 が上限**で、これは施策で利益を積んでも動かない。

この1日を和らげられれば、床が下がったぶんそのまま倍率に回せる。候補：

1. **GOLD枠の同時建玉制限** — PB GOLD と SCA GOLD が同方向に建っているときに
   後発の枚数を落とす。既存の `GoldDDMode` に重複制御の実装がある（要確認）。
2. **日次損失上限** — その日の GOLD 合計損失が閾値を超えたら以降の新規を止める。
3. **災害SLの見直し** — 1取引で −16,751円（入金の3.4%）は SL が広すぎる可能性。

ただし**単一イベントに合わせて設計すると、そのイベント専用の過学習になる**。
2024年の山（110日・全枠分散）も同時に改善するか、両窓で効くかを必ず見ること。
