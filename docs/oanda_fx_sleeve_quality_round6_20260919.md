第4ラウンドで出た **W001（PB USDJPY の slope 下限 1.2 → 1.5ATR・OOS +7,234 / IS +2,845）**は、

**外れた。1.30 から 1.50 まで、5点すべてが両窓プラスである。**

> [!important] **これは「4取引のまぐれ」ではない。**

> **「PB USDJPY の slope を 1.2 から締める」という方向は、実測に支持されている。**

## ⚠️ ただし「値」は決められない

台地の中は**滑らかではない**。

- OOS: 1.40 で **+7,429** → 1.45 で **+2,631** → 1.50 で **+7,234**
- 1.40 と 1.45 の間に1件の悪い取引が入り、1.50 で抜ける、という**階段関数**である。
- **個別の取引1件で5,000円動く。** 最良点の OOS ですら **13往復**しかない。

> [!warning] **「台地のどこかが良い」までは言えるが、「1.40 が最良」とは言えない。**
> グリッドの最良点を採るのは、第16報で V007 が示した失敗の形そのものである。
> **採るなら台地の内側**（1.35〜1.40）で、**端（1.30・1.50）は採らない。**
> 1.50（W001）は**台地の縁**であり、**IS が 1.55 で符号を失う直前**にある。
> **第4ラウンドで「最大の効果」と見えた 1.50 は、実は台地の中で IS が最も弱い点だった。**

## 採否

**台地の内側を採用候補とする。ただし「本採用」はまだしない。**

| 項目 | 値 |
|---|---|
| 採用候補 | `PbSlopeATR_UJ = 1.35`〜`1.40` |
| 効き幅（OOS） | 単利月利 **+0.020〜0.028pt**・最大DD **−0.51pt** |
| 効き幅（IS） | 単利月利 **+0.020〜0.021pt**・最大DD ±0 |
| 残る弱点 | **OOS の PB USDJPY は 13往復。** 台地であることが唯一の支え |
| 次に要る確認 | **FULL 窓**と、**本番の複利サイジング**（RefCap・risk%）の下で残るか |

> [!note] **第4ラウンドの判断（「往復数が少ないので採用しない」）は、
> 結論としては正しくなかったが、手続きとしては正しかった。**
> **1点の結果で採否を決めず、周りを刻んで台地かどうかを見た。**
> もし 1.50 だけを見て採用していたら、**IS が最も弱い点**を選んでいた。

## ⚠️ 訂正（2026-09-19・並行セッションの指摘）— 往復数を2倍に数え違えていた

**`results.csv` の `trades` と `*_n` 列は、deal 行数ではなく建玉数（＝往復数）である。**
`ml/fxqual4` の OOS deal ログで実測して確認した:

```
W000  pb_uj: entry行 18 / out行 18   → 18往復（deal 行は 36）
W001  pb_uj: entry行  8 / out行  8   →  8往復（deal 行は 16）
全 entry 行 1,375 ＝ results.csv の trades（1,375）
```

**当初は `8`（建玉数）を「8 deal」と呼び、2で割って「4往復」としていた。**
正しくは **W001 の OOS は 8往復**（対照は 18往復）、**IS は 44往復**（対照 59往復）である。
本文の該当箇所は直した（上の表の `deal` 列は元から建玉数なので数字自体は正しい）。

> [!important] **結論は変わらない。** 8往復は依然として少なく、それだけでは採用根拠にならない。
> **台地（1.30〜1.50 の5点が両窓プラス）を確認したから候補に残っている**のであって、
> 「少数取引だから台地を要求する」という判断自体は正しかった。
> **訂正されるのは数字であって、判断ではない。**

**教訓: 取引数を語るときは、その列が deal 行数か建玉数かを先に確かめる。**
`entry=0` の合計と `trades` を突き合わせれば1回で分かる。
