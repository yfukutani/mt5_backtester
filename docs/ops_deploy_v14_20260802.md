# 運用PC適用手順: MIX_EA v1.4 / MIX_EA_OANDA v1.1（アーム状態永続化・2026-08-02）

**内容:** EA再起動でPB/RSIのアーム状態・SCA日次状態が消えてシグナルを取り損ねる問題
（docs/forward_vs_backtest_20260802.md 原因B）の恒久対策。**戦略ロジック・入力・.setは一切変更なし。**
バックテスト挙動も不変（テスターでは永続化コード完全無効・回帰ゲート5窓でDEAL行完全一致確認済み）。

**今回は3端末すべてが対象**（OANDA版EAの初回改版）。

## 手順（端末ごと・各約3分）

1. リポジトリを`git pull`
2. **XM端末:** `experts/MIX_EA.mq5` を端末の `MQL5\Experts\` へ上書きコピー → MetaEditorでコンパイル
   （0エラー確認済み）。コンパイル時にチャートのEAは自動で再初期化される（チャート・.set操作は不要）
3. **OANDA FX端末 / OANDA CFD端末:** `experts/MIX_EA_OANDA.mq5` を同様にコピー → コンパイル
4. エキスパートログで確認:
   ```
   □ MIX_EA v1.4 (XM) 起動 …（OANDAは MIX_EA_OANDA v1.1 起動）
   □ 状態永続化: 保存済み状態なし（初回起動または期限切れ）   ← 初回はこれが正常
   ```
5. 以後の再起動（watchdog復旧・端末再起動）では
   `状態永続化: N枠のアーム状態を復元` が出ることを確認（受入基準）

## 動作仕様（運用で知っておくこと）

- 状態はGlobalVariable（ツール→グローバル変数、F3）に `MIXST_<magic>_<field>` 名で保存される。
  値が変わったバーだけ書き、加えて日次で全枠を再保存（GVの4週間自動削除対策）
- **初回適用時だけはアーム白紙で開始**（従来の再起動後と同じ状態）。2回目以降の再起動から効果が出る
- 長期停止（数日）からの復帰は「停止時点の状態」を復元する。停止中のバーで本来起きたはずの
  アーム更新は反映されない（連続稼働の完全代替ではない・それでも全消失よりはるかに良い）
- EAをチャートから**意図的に外して構成を変える場合**、古い状態を捨てたければ
  グローバル変数ダイアログで `MIXST_` で始まる変数を削除してから再アタッチする（通常は不要）

## 受入基準

- [ ] 3端末とも起動ログにv1.4/v1.1と「状態永続化」行が出る
- [ ] 適用後最初の再起動で「N枠のアーム状態を復元」が出る（watchdogの次回復旧時でも可）
- [ ] 適用後7日間、取引・SCA_RANGE出力が従来どおり（挙動変化ゼロ）

## ロールバック

`git checkout <前コミット> -- experts/MIX_EA.mq5 experts/MIX_EA_OANDA.mq5` → 再コンパイル。
GVは残っても旧版は読まないため無害（気になる場合はF3ダイアログでMIXST_*を削除）。
