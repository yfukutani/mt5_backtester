文字化け：なし（対象 Python は UTF-8 として構文解析可）。

- `sca_hours.py` の「UTC hour」という表現は誤りです。EA は M15 バーのサーバー時刻 `dt.hour` を渡します。一方、deal の UNIX 秒はサーバー壁時計をそのまま符号化した値なので、`timezone.utc` で復号した hour は現状このサーバー時刻と一致します。X001 の 10–11 時指定自体はズレていませんが、「実 UTC」と誤認すると将来の移植・再集計で壊れます。

- 「`scaDone` による1日1発」は誤りです。実装は `scaTradedL` と `scaTradedS` の方向別フラグです。09時にフィルタ拒否されてもどちらも立たず、10時・11時で再評価・発注されます。さらに、同日に買いと売りを各1回まで持てます。従って、09時行を消すだけの事前損益予想、特に X002−X001 が USDJPY の09時損益に一致すべきという期待は成立しません。

- `RevBoost` の扱いが事前予想から抜けています。GBPJPY の6倍は「買いかつ当日レンジ drift<0」または「売りかつ drift>0」で判定されます。09時を止めても drift 自体は変わりませんが、後続で入る方向・時点が変わるため、Boost 対象が消える／新規に6倍対象になる可能性があります。単純なログ行削除との差が大きくなり得ます。

- `analyze.py` は「枠の和＝ブック」の恒等式を検査していません。候補−対照の差分同士だけを比べているため、両者に同じ未配賦が残れば `未配賦=0` になります。`fxmargin3/measure.py` の magic=0 決済を `position_id` の建玉 magic へ戻す第16報修正は継承されていますが、各 run で絶対値の `sum(sleeve_net) − net` も別途出す必要があります。

- PB の slope 締めで、SL 距離や risk 2% が閾値変更そのもので変わるわけではありません。`sld=ATR×2.0` と risk 基準は固定です。ただし通過するバー集合が変わるため、採用された取引の ATR・SL 距離・ロットは間接的に変わります。また、抑止された PB シグナルは単なる「1取引削除」ではなく、反対ポジションを閉じて反転する処理も抑止します。取引数半減や損益を LOO のバー数から予想するのは過大に単純化されています。
