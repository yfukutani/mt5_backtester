## 1. 最小の移植（採用候補3件・本番現行サイジングのまま）

**ラボの input をそのまま移植しない。** ラボの `RsiMechMask_UJ` などは
**掃引のためのつまみ**であり、本番に要るのは**採用値がハードコードされた状態**だけである。
つまみを移すと、本番EAに「誤って動かせる値」が増える。

### 1.1 PB USDJPY の slope 下限 1.2 → 1.40

**1行。** `MIX_EA_OANDA.mq5` の PB USDJPY 枠定義（`x.magic=20260622` の行の直後）に足す:

```cpp
x.slopeMinATR=1.40;   // 第17報 fxqual6: 1.30〜1.50 の5点が両窓プラス（台地の内側を採る）
```

**根拠:** [round6](oanda_fx_sleeve_quality_round6_20260919.md)。
**プリセット `pb.slopeMinATR=1.2` を継承している枠なので、個別に上書きする**
（PB GBPJPY と PB AUDJPY に影響させない）。

### 1.2 RSI USDJPY の機構ゲート（R単独・B単独を落とす）

**6行。** `ProcRSI()` の `bool eb=...` / `bool es=...` の直後に足す。
**本番EAには `rbuy` / `bbuy` / `dpb` / `rsell` / `bsell` / `dps` が
ラボと同名・同式で存在する**ので、そのまま使える:

```cpp
   // 第17報 fxqual3 V001: RSI USDJPY は「R単独」「B単独」が両窓とも負ける。
   // 落とした足ではフラグを消費しない（消費は発注ブロックの中なので自動的にそうなる）。
   if(S[i].magic==20260610){
      int cb=(rbuy?1:0)|(bbuy?2:0)|(dpb?4:0);
      if(cb==1 || cb==2) eb=false;
      int cs=(rsell?1:0)|(bsell?2:0)|(dps?4:0);
      if(cs==1 || cs==2) es=false;
   }
```

**根拠:** [round3](oanda_fx_sleeve_quality_round3_20260919.md)。
ラボの `RsiMechMask_UJ=124` は `1<<(code−1)` の OR で、**124 = コード3〜7を許可**
＝ **コード1（R単独）とコード2（B単独）だけを落とす**。上のコードと等価である。

### 1.3 SCA USDJPY のレンジ幅下限 0.0048

**4行。** `ProcSCA()` の買い側・売り側それぞれ、`if(dist>0){` の直後に足す:

```cpp
      // 第17報 fxqual10/fxqualfloor: SCA USDJPY は |entry−sl|/entry が狭い取引が負ける。
      // 0.0042〜0.0048 が台地（0.0060 は IS のスパイクなので採らない）。
      if(S[i].magic==20261000 && dist/ask < 0.0048) { /* 発注しない */ } else {
```

**⚠️ 分母は `ask`（売り側は `bid`）＝その時点の価格である。** レンジ幅そのものではない。
ラボの `ScaFilEntryOK()` が `dist/entry` を見ており、`entry` に `ask`/`bid` が渡っている。
**ここを取り違えると別の条件になる**（[round5 の訂正](oanda_fx_sleeve_quality_round5_20260919.md)）。

**根拠:** [レンジ幅下限の全曲線](oanda_fx_sca_range_floor_20260919.md)。

### 1.4 移植後に必ずやること — **ビット一致の確認**

**本番EAとラボEAで、同じ窓・同じ設定を走らせて1円まで一致させる。**
`portfolio_ea.md` が「全5戦略が個別EAとビット一致を確認」と同じ作法を取っている。

| 確認 | 期待値（本番現行サイジング・OOS 2016.11.09–2021.06.20） |
|---|---|
| 移植**前**の本番EA | **+117,843 / 残高DD 5.2719% / 1,375取引**（ラボの対照と一致すること） |
| 移植**後**の本番EA | **+131,420 / 残高DD 4.34% / 1,136取引**（ラボの `F007` と一致すること） |

**移植前が一致しなければ、9月のラボ変更のどれかが既定で本番と挙動を変えている**
ということなので、そこで止めて原因を特定する。

## 2. 複利サイジングの移植は別の話（**規模が違う**）

本日の **OOS 2.488%（倍率1）/ 3.849%（倍率2）**は、
**`FxRiskMask=31` / `FxRiskRefCap=0` / `RefCap_*=0` / `MarginCapPct=90`** を前提にしている。
これらは**本番EAに1つも無い**。

移植するものは:

| 要素 | 内容 |
|---|---|
| `FxRiskOn()` と `FxRiskMask` | RSI 3枠・SCA 2枠を equity 連動の risk% に切り替える |
| `ScaBaseLot()` の risk% 経路 | **09-15 のバグ修正**（SCA が `LotRisk()` を通らず固定ロットを直接計算していた） |
| `RefCap_*=0` の扱い | PB 2枠・Carry を equity 連動にする |
| `MarginCapLot()` と `MarginCapPct` | 使用証拠金 / equity の上限 |

**`Clamp()` は本番EAにも存在する**（`trade.Buy(Clamp(sym,lot),...)`）が、
**証拠金cap の実装は入っていない。**

> [!warning] **順番を守ること。**
> **1章（候補3件・本番現行サイジング）と2章（複利サイジング）は別々に移植し、
> それぞれでビット一致を取る。** 一度に入れると、ずれたときに原因を切り分けられない。
> **1章だけでも 0.386% → 0.425%（+0.040pt）・最大DD 5.27% → 4.34% の改善になる。**

## 3. まだ決まっていないこと（ユーザーの判断事項）

**複利サイジングを入れるかどうかは、許容DDの問題である。**

| 構成 | OOS 幾何月利 | 残高DD | **equityDD** |
|---|---:|---:|---:|
| 本番現行 ＋ 候補3件（**1章だけ**） | **0.425%** | **4.34%** | **6.06%** |
| 全複利・倍率1 ＋ 候補3件 | **2.488%** | 23.45% | **34.57%** |
| 全複利・倍率2 ＋ 候補3件 | **3.849%** | 46.30% | **62.07%** |

**どれも元本割れは無い。** だが **equity DD は 6% / 35% / 62% と桁が違う。**
**収益だけで選べる問題ではない。**
