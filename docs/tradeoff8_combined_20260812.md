# 8トレードオフ案・組合せ検証（2026-08-12）

## 結論

**8案をそのまま全部採用する判定は NO。** 純利益は増えるが、最大DD%が悪化し、指定指標の「純利益÷最大DD%」は低下したため、ポートフォリオ全体の収益性をリスク込みで改善したとは判定しない。

一方、256部分集合を全dealで総当たりした結果、**#2 Funding BTC、#3 PB USDJPY、#4 PB GBPJPY、#7 Carry AUDJPY、#8 BfxRev BTC の5案**が推奨組合せである。この組合せは baseline に対して純利益、最大DD%、リターンDD比のすべてを改善した。

## 条件と方法

- 基準は検証開始時点の `configs/*.yaml`。本番yamlは変更していない。
- 個別窓: IS 2021.06.21–2026.06.20、OOS 2016.06.21–2021.06.20。
- BfxRev OOSは元データ開始に合わせ2016.12.01開始、FundingRev OOSは2019.09.01開始。
- portfolioは15 config、各100,000、合計初期資金1,500,000。指定configは全件実在し、VBOは含めていない。
- SCA 3本は `every_tick`、その他は本番configのmodelを維持。
- portfolioの各baseline deal列と、変更対象8本のcandidate deal列をMT5で直列測定した。candidate/LOO/256部分集合は、その保存済みdeal列を `mt5bt portfolio` と同じ順序・計算式で時系列合算した。これは各LOOで不変なEAを再起動する代わりに同一deal列を再利用した正確な再構成であり、推定ではない。
- `リターンDD比` は依頼どおり `純利益÷最大DD%`（1 DD百分率ポイント当たりの利益）。参考としてCLI標準の `純利益÷最大DD額` も記録した。

## ステップ2: 8案同時適用時の個別測定

8案はすべて異なるconfig/スリーブに属し、同一スリーブに複数変更はない。このため全案適用時の各スリーブ入力はステップ1の単独適用入力とバイト上同値であり、MT5の個別結果も上表と同じである。スリーブを跨ぐ相互作用は個別tester内には存在せず、次節のdeal時系列合算で検証した。
