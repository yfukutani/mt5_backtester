### そのずれの原因は特定された — **Carry のスワップが更新されていた**

原因究明は並行セッション（第18報）の功績である
（[oanda_fx_carry_swap_drift_20260919.md](oanda_fx_carry_swap_drift_20260919.md)）。
こちらでも **deal ログを1対1で突き合わせて独立に再現した**:

```
A: ml/fxrisk1/run_deals/fr_full_R001_20260909050904_6980_deals.csv   5938 deals
B: ml/fxqualcfm/run_deals/mc_full_F000_20260919005507_6f5f_deals.csv 5938 deals

key（時刻・magic・entry・方向・ロット・価格）の不一致:  0 件
損益が違う deal:                                        13 件・合計 −4,070 円
```

**約定は完全に同じで、違うのは13件の損益だけ。** 内訳:

| magic | 差 |
|---:|---:|
| **20260650**（Carry AUDJPY） | **−3,388** |
| **0**（窓末の建玉をテスターが強制決済した deal） | **−682** |
| 合計 | **−4,070** |

**`magic=0` の実体も Carry AUDJPY の建玉**なので、`position_id` から建玉時 magic へ
引き直せば **全部 Carry** である（第16報の配賦修正）。
**MT5 のテスターは銘柄仕様の「いまのスワップ値」を履歴全体に当てる**ので、
業者が更新すれば同じ設定・同じ期間でも Carry の損益は変わる。

> [!important] **これは「EA 変更が不変でなかった」ことの証拠ではない。逆である。**
> 09-09 から 09-18 のあいだに EA には **553行の挿入・50行の削除**が入っているが、
> **Carry 以外の8枠は 2,969取引にわたって1円も動いていない。**
> **「新 input は既定値で不変」という主張の、最も強い裏付けになっている。**

### ⚠️ ラウンドまたぎの比較で踏む罠は2つある

**枠別 CSV（`results.csv` の `*_net` 列）で同じ2つを比べると、まったく違う絵が出る:**

| 枠 | R001 FULL | F000 FULL | 差 |
|---|---:|---:|---:|
| carry_net | 56,128 | **105,291** | **+49,163** |
| pair_net | 15,093 | 15,048 | −45 |
| 他7枠 | — | — | **すべて ±0** |

**この +49,163 はスワップではない。第16報の配賦修正である。**
`ml/fxrisk1` の results.csv は**修正前**の集計で、窓末の建玉が枠から丸ごと落ちている
（R001 FULL は枠の和 325,896 に対しブック 379,084 ＝ **未配賦 53,188**）。
そして **53,233 − 4,070 = 49,163** で、窓末建玉の 09-09 時点の値と1円まで合う。

| 罠 | 中身 |
|---|---|
| **スワップのドリフト** | Carry の損益は**走らせた日**の関数。同じ日に対照と案を走らせれば問題ない |
| **配賦の版** | **第16報より前のラウンドの枠別列は、窓末の建玉が落ちている。** 引き算してはいけない |

**deal ログで比べれば両方とも避けられる**（配賦は `position_id` で引き直す。
`magic=0` を引き直さないと「正体不明の magic 0」が残るので注意）。

### ⚠️⚠️ F002/F004 は `ml/fxrisk1` の R036/R037 の**再現ではない**（測る前に書く）

`FxRiskMask` のビット割り当ては **bit0=RSI UJ / bit1=RSI EU / bit2=RSI GU /
bit3=SCA UJ / bit4=SCA GJ** で（`FxRiskOn(x, n)` の呼び出し・EA 1103/1110/1118/1216/1237行）、
**`31` は5枠すべて**を意味する。

**ところが `ml/fxrisk1`（2026-09-09）の時点では、bit3/bit4 は無効だった。**
EA のコメント（`ScaBaseLot` の直前）にこう書かれている:

> **【バグ修正 2026-09-15】** `FxRiskOn()` は SCA枠(bit3/bit4)に `useRisk` を立てるが、
> **SCA の発注経路は `LotRisk()` を通らず固定ロットを直接計算していた**ため、
> `FxRiskMask` の bit3/bit4 が完全に無効だった。fxrisk1ラウンドでは
> R008(mask=8)/R009(mask=16)/R016-R021(mask=24) が mask=0 の R003 と
> **純益・DD・取引数まで完全一致**しており、これが実測の証拠である。

`oanda_fx_risk_sizing_20260915.md` が R036/R037 の mask を **「7実効」**と書いているのはそのためである。

**そして、そのバグは本ラウンドが使うバイナリでは直っている**（blob `e016ab05` の
`ScaBaseLot` は `if(S[i].useRisk && dist>0.0) return LotRisk(...)` を通る）。

> [!warning] **したがって F002/F004 は「R036/R037」ではない。**
> **SCA 2枠にも risk% サイジングが掛かる、より強い構成**である。
> しかも **SCA の risk%化は逆効果と実測済み**である
> （`risk%サイジングは取引の重みづけを変える`: SCA はレンジ幅が SL 距離なので
>   「狭いレンジ＝大きいロット」になり、狭いレンジが赤字な枠では損を拡大する。
>   +16,339 → −5,881円）。**F002/F004 は R036/R037 より悪く出るはずである。**
>
> **それでも F002 vs F003・F004 vs F005 の比較は有効である**——
> 同じサイジングで候補の有無だけが違うからである。
> **本ラウンドが答える問い（候補は複利サイジングでも残るか）には答えられる。**
> 答えられないのは「R036/R037 そのものの月利」であり、それは本ラウンドの目的ではない。

**測る前に決めておく判定:** `F002` の OOS が **+755,318 に近ければ** bit3/bit4 は
まだ効いていない（＝R036 の再現）。**大きく違えば効いている**（＝別構成）。
**後者だと予想する。**

#### 実測 — 予想は半分当たり、半分外れた

| | `ml/fxrisk1` R036（09-09） | **`F002`（09-19）** |
|---|---:|---:|
| OOS 純益 | +755,318 | **+989,367** |
| OOS 幾何月利 | 1.69% | **2.004%** |
| OOS 最大DD | 23.1% | **34.31%** |

- **「別構成になる」は当たり。** +234,049円の差は、スワップのドリフト（Carry の数千円）では
  説明できない。**bit3/bit4 が効いて SCA 2枠にも risk% が掛かっている。**
- **「R036 より悪く出る」は外れた。** OOS は **1.69% → 2.004%** と**良くなっている**
  （ただし最大DD も 23.1% → 34.31% と大きく増えている）。

**「SCA の risk%化は逆効果」という既存の記録と、符号が逆に見える。**
だが**その記録は別の機構での測定**である——`FxRiskMask` の bit3/bit4 は
09-15 まで**完全な no-op** だったのだから、`fxrisk1` の R008/R009/R016-R021 は
「SCA を risk%化した構成」を測っていない（測れていなかった）。
**`F002` は「SCA も risk%化した全複利構成」の、おそらく初めての実測である。**

> [!warning] **この数字を「改善」と読んではいけない。**
> 本ラウンドの目的は**採用候補の確認**であって、サイジングの探索ではない。
> `F002` は**対照**であり、DD も 23.1% → 34.31% に増えている。
> **証拠金が足りるか（実行可能か）は測っていない**（`MarginCapPct=0` なので
> cap ログに使用率が出ない）。`R037` が「確定利益だけでは必要証拠金に届かず、
> 時間の 3.5〜5.2% を含み益に依存して建てている」と判定されたのと同じ検査が要る。
> **ここでは「別構成だった」という事実だけを記録し、採否は論じない。**

## 2. 事前の予想（測る前に書く）

- **FULL 窓では候補2件とも残る**と予想する。OOS/IS の両方で同符号なので、
  その和である FULL で符号が変わるほうが不自然である。
- **R036 / R037 では効き幅の「ポイント」が下がる**と予想する。
  複利で伸びるのは早い時期に勝った枠で、**PB USDJPY は OOS で元々マイナスの枠**である。
  金額は増えても、月利のポイント換算では小さくなると見る。
- **F006（SCA UJ レンジ幅下限）は +3,991 / +3,393 になるはず**である
  （`ml/fxqual8` の RV06 の枠別Δ。枠別効果の加算性は4例で確認済み）。
  **ずれたら加算性の反例**なので、そちらのほうが情報量が大きい。
- **最優先の合否は口座破綻（元本割れ）の有無。** R037 は最大DD 41.8% なので、
  候補が DD を悪化させる方向に出たら、**金額が増えても採らない。**
