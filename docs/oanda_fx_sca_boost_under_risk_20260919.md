# Claude 側の第15ラウンド案 — 反転日ブーストは、risk% 化で意味が変わってしまっている

> Codex は第14回で「**未測定軸として再提案できるものはありません**」と答えた
> （[原文](codex_oafx_round14_20260919.md)）。**こちらは1件だけ反例を見つけた。**
> **Codex の棚卸しにも、`rejected_strategies.md` にも載っていない。**

## 1. 何が起きているか

SCA 2枠には **反転日ブースト**がある。前日のドリフトと逆向きにブレイクした日だけ、
ロットに定数を掛ける。

| 枠 | `scaBoostMult` | EA の場所 |
|---|---:|---|
| SCA USDJPY | **2.0** | [MIX_EA_SIMVERIFY.mq5:1360](../experts/MIX_EA_SIMVERIFY.mq5) |
| SCA GBPJPY | **6.0** | [MIX_EA_SIMVERIFY.mq5:1381](../experts/MIX_EA_SIMVERIFY.mq5) |

**どちらもハードコードで、input ではない。**

この 6.0 は 2026-08 に 2.0 → 3.0 → 4.0 → 6.0 と段階的に上げて採用した値である
（[round2](new_strategies_round2_20260805.md) / [codex500 verification2](codex500_verification2_20260810.md) /
[codex500 round3](codex500_round3_20260811.md)）。

> [!important] **問題は、その掃引が全部「固定 0.01ロット・枠単独」で行われたことである。**
> EA のコメントが自分で書いている:
>
> > **「Boost4.5 は 0.01×4.5＝0.045 がロットステップで 0.04 に丸められ 4.0 と完全同値
> > ＝0.01ロット基準では整数倍しか意味を持たない」**
>
> **つまり 6.0 は「0.01刻みで表現できる整数倍の中での最良」であって、
> 連続値の中での最適ではない。** そして当時の判定は**枠単独・固定ロット**である。

## 2. risk% 化で、この定数の意味が変わった

現構成は `FxRiskMask=31` で **SCA 2枠にも risk% が掛かっている**（`FxRiskOn(x,3)` / `(x,4)`）。
発注経路はこうなる（[ProcSCA](../experts/MIX_EA_SIMVERIFY.mq5)・3505行付近）:

```
lot = ScaBaseLot(i,dist)        // = LotRisk() = equity × 0.5% ÷ SL距離（すでに Clamp 済み）
if(反転日) lot *= scaBoostMult  // ← 6.0
lotL = Clamp(sym, lot, i)       // もう一度 Clamp
```

**したがって SCA GBPJPY は、反転日に equity の 3.0% を1取引でリスクに晒している**
（0.5% × 6）。倍率2 では **6.0%**。SCA USDJPY は 1.0% / 2.0%。
**他の8枠はすべて 0.5%（倍率1）である。**

> [!warning] **6.0 という数字は、「0.01ロットの6倍＝0.06ロット」という
> 無害な文脈で選ばれた。いまそれは「口座の3%を1発で賭ける」を意味している。
> 同じ定数が、まったく違う量を表している。**

## 3. なぜこれが「まだ測っていない」と言えるか

| 既測定のもの | それとどう違うか |
|---|---|
| 第12ラウンド C群（`Mult_SCA_GBPJPY` = 0.5 / 0.25 / 0） | **枠ぜんぶの重み**を下げる。反転日と平常日を同じ比率で下げるので、**枠の内部配分は変わらない** |
| `ScaRevOnlyMask` / `ScaRevDropMask`（第8ラウンド） | 反転日**だけ**取る／反転日を**捨てる**の二択。**中間が無い** |
| Boost_Mult 2→3→4→6 の掃引（2026-08） | **固定 0.01ロット・枠単独・整数倍のみ**。risk% でも複利でもない |
| Codex 第50案 #42「GJ の逆ドリフト・ブーストだけ逓減」 | **提案のみで未実測**（[margin50](codex_oafx_margin50_20260915.md) の表で「○」のまま） |

**Codex 自身が2026-09-15 に同じ形を提案して、そのまま測られずに残っている。**
Codex が第14回で「未測定軸は無い」と答えたのは、この1件を取りこぼしている。

## 4. 測り方（EA に input を1組足す）

```
input double ScaBoostMult_UJ = 0.0;   // 0 = 現行値（2.0）を使う＝完全に inert
input double ScaBoostMult_GJ = 0.0;   // 0 = 現行値（6.0）
```

`AddSleeve` の直前で `if(ScaBoostMult_GJ>0.0) x.scaBoostMult=ScaBoostMult_GJ;` とするだけ。
**既定 0 で1ビットも変わらない**ので、回帰試験で inert を証明できる。

| 案 | 内容 | ねらい |
|---|---|---|
| W000 | 対照（回帰試験） | `V000` と一致すること |
| W001〜W004 | **GJ の boost = 4.0 / 3.0 / 2.0 / 1.0** | **1.0 は「ブーストを外す」＝下界。ここが最良なら 6.0 は過学習** |
| W005 | GJ の boost = 8.0 | **反証点。上げても良くなるなら「6は低すぎた」であって「高すぎた」ではない** |
| W006〜W007 | UJ の boost = 1.0 / 4.0 | UJ 側は 2.0 のまま一度も再検討されていない |

## 5. 事前の予想 — **中くらい。ただし方向は読めない**

- **効き幅は第12〜13ラウンドより大きいはず。** 反転日は SCA GBPJPY の取引の一部だが、
  **ロットが6倍なので equity への寄与では支配的**である。第23報で
  「`RevBoost` の6倍があるので『リスク当たり』と『equity 当たり』で符号が割れる」
  と自己訂正したのは、まさにこの重みのことだった。
  **±0.1〜0.5pt の幅が出ると予想する**（第12・13ラウンドの軸は ±0.03pt 程度だった）。
- **方向は読めない。** 2026-08 の掃引は 2→3→4→6 と**単調に良くなり続けた**
  （固定ロット・枠単独では）。単調なら 8.0 でも良いことになるが、
  **複利では「1発で3%」が DD 経路を変えるので、同じ単調性は期待できない。**
- **DD は下げる方向が本命。** 第23報の「月利÷DD は `sca_gj` の重み 0.25 で最大」は
  枠ぜんぶの重みの話だったが、**もし効いていたのが反転日の6倍のほうなら、
  boost だけ下げて平常日を残せば、あの改善を IS を壊さずに取れる可能性がある。**
  第12ラウンド `Q004`（OOS +0.197pt / IS −0.683pt）が IS を壊したのは、
  **平常日まで一緒に下げたからかもしれない。** これが本案の一番の狙いである。

## 6. 走らせる前に deal ログで確認した（`ml/fxqual13/boost_split.py`）

「確認してから走らせる」と書いたので、確認した。
`T000`（倍率1・完全複利）の約定ログを2群に割る。

> [!warning] 🔴 **最初の判別は間違っていた。自分で訂正する。**
> 第1版（`boost_split.py`）は「リスク額 ÷ **確定損益の累積**」を equity の代理にして
> 1.5% を閾値にし、**「分布がきれいに二峰なので誤判定はほぼ無い」と書いた。
> それは分位の読み違いである。** IS の `sca_gj` は p75 0.962 / p90 3.220 で、
> **15%（約102取引）が 0.96〜3.22% の谷に落ちている。谷は埋まっていた。**
> 原因は代理の質で、**Carry が数か月〜数年ポジションを持つため確定残高と実 equity が
> 大きく乖離する**（リスク率の max が 6.106% ＝ 設計値 3.0% の2倍になっていた）。
>
> **第2版（`boost_split2.py`）で判別を作り直した。**
> `lot = equity × riskPct ÷ SL距離` なので、**同じ枠の時間的に近い取引どうしなら
> equity はほぼ同じ**である。したがって
> **「その取引のリスク額 ÷ 近傍20取引のリスク額の中央値」**は equity の推定誤差に依らない。
> boost は 6倍なので、平常日ばかりの近傍に対して比は 6 に近づく。

| 判別 | `sca_gj` boost 取引数 | OOS 純益 | IS 純益 | 谷に居る割合 |
|---|---:|---:|---:|---:|
| 第1版（残高比 1.5%） | 159 / 161 | +594,203 | −566,155 | **15%（不良）** |
| **第2版（近傍中央値比 3.0）** | **159 / 161** | **+594,203** | **−566,155** | **0.2〜0.3%（良）** |

> [!important] **`sca_gj` は2つの独立な判別が1円まで一致した。この数字は信用してよい。**
> **`sca_uj` は一致しない**（OOS boost 10 対 17・IS 49 対 36）。
> **UJ の boost は 2倍しかなく、SL距離のばらつきに埋もれる**（谷に 16〜18% が居る）。

### 分かったこと（3つ）

1. 🔴 **`sca_gj` は boost 群も plain 群も、リスク当たりでは IS が両方マイナス。**
   OOS の枠純益 +426,099 は **boost 群だけ**が作っており、
   IS の −719,706 も **79% が boost 群**である。
   **同じ群が窓をまたいで符号を反転させ、そこに6倍のロットが乗っている。**
2. 🔴 **`sca_gj` の plain 群は両窓マイナス**（−0.094R / −0.029R）。
   「反転日だけ取る」は第8ラウンドで測って採用ゼロだった（`ScaRevOnlyMask`）が、
   **あれは0か1かの二択だった。倍率を連続で動かす軸は残っている。**
3. ⚠️ **第18報の「SCA GBPJPY の枠純益はリバーサル群だけから出ている」は
   固定ロットでの分解だった。複利で割り直すと IS では boost 群が主たる損失源になる。**
   第22報の「複利では帰属が変わる」の4例目。

### これが予想を変える

前節で「IS を壊さずに取れる可能性がある」と書いたが、**そこまで楽観できない。**
**IS では boost も plain も両方マイナスなので、boost だけ下げても IS の改善幅は
`sca_gj` 全体の一部にとどまる。** しかも第12ラウンド C群は
**枠ぜんぶの重みを下げたのに IS が悪化した**（−0.136〜−0.327pt）。
**「マイナスの枠を軽くすると IS が悪化する」という、直感に反する挙動が既に実測されている。**

> [!caution] **したがって本案の見込みは「中」ではなく「五分五分」に下げる。**
> **効き幅は大きい（±0.1〜0.5pt）が、符号が読めない。**
> 測る価値はある（**効き幅が大きい軸が他に残っていない**ため）が、
> **「これで6%に届く」とは考えていない。** 6%までは倍率1 で 2.4倍である。
