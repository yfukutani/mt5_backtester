# OANDA FX 複利掃引

月利5%を目指す未検証軸として、FX 9枠のRefCap 4値（0・78000・250000・500000）、
全体倍率1・2・3、現行重み／採用形重みの24案を比較する。
C001は現行（RefCap=78000、倍率1、全重み1.0）。
採用形は Mult_SCA_GBPJPY と Mult_CARRY だけ0.5、他は1.0。
3枠のRefCapは常に同じ値で、ラボは明示的に無効化する。

RefCap=0でequity連動になるのは、risk%枠のPB USDJPY（20260622）、
PB GBPJPY（20260627）、Carry（20260650）の3枠のみ。
残る6枠は基本ロット0.01の固定ロット枠で、倍率・重みは効くが複利にはならない。

主窓はFULL（2016.11.09～2026.06.20、115ヶ月）、比較窓はOOS
（2016.11.09～2021.06.20、55ヶ月）。計48run、入金50万円、レバレッジ25。
端末設定は元ハーネスのXM端末を継承するため、OANDAの実フィード測定とは区別する。

results.csvには総取引数 trades、最終残高 final_balance、出典 balance_source、
暫定破綻フラグ blown、dealsの保存先、枠別損益・取引数を残す。
同じ窓のC001実測取引数の50%未満なら blown=True、50%以上ならFalse。
取引数減少は破綻の暫定代理指標であり、破綻の確定診断ではない。
過去の目安（FULL 2969／OOS 1375）は判定の固定値に使わない。
各窓でC001を先に取得し、再開時は保存済み基準を復元する。
C001取得失敗時は結果を保存して中断する。欠測の判定は空欄であり、Falseではない。

残高はsummaryを優先し、取得できなければ入金＋全dealのprofit合計で代用する。
EAのprofitはスワップ・手数料込み。残高出典がunavailableなら残高も空欄。
monthly_pctは継承元と同じ入金比の単純月平均で、複利月利の評価指標ではない。
評価スクリプト adjudicate.py は作成しない。

提案の再生成は `python ml/fxcomp1/generate_proposals.py`。
測定スクリプトは `ml/fxcomp1/measure.py`（直列・再開可能、1run上限5400秒）。
OKかつdealファイルが残るrunをスキップし、失敗runは再試行する。
EA差し替え検知、スリープ抑止、端末回収、毎runの保存を継承する。
測定時はXM端末を使用・回収するため、他の掃引が終了してから起動すること。
今回の作業ではMT5測定は実行していない。
