# OANDA FX 9枠の重み再配分

指定グリッドは45案（A=4、B=15、C=6、D=8、E=8、F=4）、IS/OOSで90run。
DはCarryまたはRSI EURUSDの片方だけ、FはSCA GBPJPYとCarryの両方を変更する。
Eは指定された固定グリッドであり、測定結果からの推定値ではない。

Python 3.7以降・標準ライブラリのみ。各スクリプトは自身のディレクトリを基準に動く。

```text
python ml/fxweight1/generate_proposals.py
python ml/fxweight1/adjudicate.py
python ml/fxweight1/attribution.py
python -B -m unittest discover -s ml/fxweight1 -p test_harness.py -v
```

今回の作成作業ではMT5測定を実行していない。将来、測定するときだけ
`python ml/fxweight1/measure.py` を使う。同じコマンドで再開できる。
成功してdealログが存在する案ID・窓の組をスキップし、失敗とログ欠損は再試行する。
結果は1runごとに追記・flush・fsyncする。既存結果と案のパラメータが違えば停止する。
同時に複数のmeasureを起動しない。CSV自体が破損した場合は修復してから再開する。

`BASE`はfxmult1の`BOOK`と同じ内容。EAガード、スリープ抑止、端末回収、枠別集計を継承。
元と同じXM端末・銘柄で測る設定なので、OANDA本番判断にはOANDAでの確認が必要。
EAハッシュ比較は元と同じくプロセス開始時と各run直前の比較である。

集計は`results.csv`の`deals`から`profit`だけを使用する。
月利は純益÷500,000÷窓月数×100。DDは含み損込みのequityではなく、元の
`curve()`と同じ決済損益累積のピークからの円建て落ち込み。
DD予算20/25/30%の範囲内で月利だけを順位付けし、同率は同順位で残す。
現行差は同窓・全倍率1の実測から算出し、基準がなければ未測定と表示する。
内挿・外挿・deal損益の倍率変換は行わない。

両窓共通の上位3位（`--top`で変更可能）は参考候補。合格判断は両窓で予算内月利最大が
一致するかで行い、一致しなければ保留。未完了が残る比較も暫定扱い。
FULLはmeasureの対象外。後日別途実測した上位案の同形式結果があれば集計できる。
`--results`と`--proposals`で入力CSVを指定でき、報告は標準出力に出る。

attributionは窓・予算別上位の和集合と現行を対象に、全ての利用可能な窓を表示する。
負寄与率の分母は期間中に純損失となった枠の損失合計で、利益枠の相殺分は別表示。
同秒約定と初回損失の取りこぼしを防ぐため、期間の切り出しだけは日時条件ではなく
元のcurveと同じソート順のピーク直後から底までの約定位置を使う。

検証環境では既定Pythonが3.6、設定された3.14は実行権限がなかったため、
`from __future__ import annotations`だけをメモリ上で除いた状態で4テストを実行した。
配布ソースは変更せず、MT5や端末回収処理は呼び出していない。
